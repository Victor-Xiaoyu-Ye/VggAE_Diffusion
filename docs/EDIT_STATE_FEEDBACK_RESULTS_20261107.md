# Stage66实际结果：闭环接通，但联合校准多数更新未被接受

审阅目录：`D:/中转站/VGGAE/scale/edit_state_feedback_v1`。
代码对应Stage66，manifest记录的6个代码文件hash全部与本地一致。
本轮为冻结Stage65模型上的推理校准，没有新增权重训练。

## 结论

五路24例全部完成，反馈真实影响后续视频，生产910B运行和显存可行。
RAE闭环带来小幅非编辑区变化下降，但RGB闭环有近似收益；尚无稳定的
RAE独有新增视觉优势。更具体的问题是：多数联合求解的候选比初始解差，
被best-state保护恢复。`applied=true`只代表实际写回，不代表求解改进。
这轮不能作为decoder校准已普遍有效、几何贡献成立或SOTA的证据。

继续保留用户指定的RAE编辑状态＋VACE＋对应约束方向。当前优先处理
数值求解与真实状态更新，再评估画面收益，不重新重训AE或盲目扩大数据。

不是编辑正确率，帧差也不是时序质量分数。

## 机制审计：成功写回与成功求解是两件事

| 检查 | RGBjoint | RAEjoint |
|---|---:|---:|
| 实际写回 | 72/72 | 72/72 |
| 数值fallback | 0 | 0 |
| 有梯度检查 | 72/72 | 72/72 |
| 接受更低objective的新解 | 5/72 | 22/72 |
| 至少一次接受新解的case | 2/24 | 10/24 |
| 四轮候选均未胜出，恢复初始解 | 67/72 | 50/72 |

三次反馈实际为step20/25/28、sigma约0.59964/0.37472/0.17631。
每例30条源对应边、每事件4轮。RAE每事件90次decoder response，共6480次。
没有梯度断路、prefix误写、事件漏接或数值fallback证据。

但RAE被拒绝的50次事件中，bridge状态变化RMS中位只有1.13e-5，clean latent
修正RMS仍有0.05990；接受的22次分别为0.01268和0.10548。14例一次新解都
没有接受。证据支持许多事件主要重新注入已有decoder参考，而非得到新的
联合优化状态。半精度重建/重复可靠性门控可解释部分微小bridge变化，但
缺少`.pt`，不能独立确认这些变化的唯一来源。

拒绝事件首轮objective相对初始值的中位倍数：RAE2.33、RGB4.51。
固定Adam步长0.03、很少迭代且没有回溯搜索，是需要优先验证的过冲原因；
不是仅凭日志已经证明的唯一原因。RAE接受事件的内部temporal误差全部
下降，仍不能等同最终视觉改善。

源图可达性相对旧proposal新增可靠覆盖平均约1.264%（按含padding的518
方形画布计算）。当前24例主要是已有参考的修正，不能替代强遮挡、重现、
对应缺失条件下对decoder先验的验证。

## 下一步优先级

1. 保留现有方法方向，先把数值求解改为带目标下降检查的逐块回溯/自适应
   步长，记录接受率与真实delta；RGB的二次型问题应作为可靠强对照。
   `applied`与`objective_improved`分开报告，不用画质门槛阻止后续输出。
2. 在同一批自然视频重跑完整方法，确认接受的新编辑状态能改善最终输出，
   而非仅强化旧proposal。区分固定RGBcontext与新state/velocity是否冲突。
3. 错误锚帧单独记录；优化求解器不能修正“蓝钢笔变蓝图纸”的语义错误。
   对已经可用的蝴蝶、木纹等样例继续验证真实细节与动态收益。扩大数据或
   蒸馏操作模块应建立在有效状态更新之上，不把本轮弱增益直接包装成贡献。

以上是审阅后的建议，本轮没有修改训练/采样实现或启动新实验。

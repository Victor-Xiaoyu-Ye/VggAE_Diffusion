# VGGT as RAE：从视频编码器走向可更新的生成场景表示

2026-09-22。针对用户最新的“像 MIRA 一样找到有说服力的故事，拓展 VGGT as RAE”请求。本文是研究建议，不是已确认创新、用户已批准的新架构或实验结果。没有修改训练代码、启动或停止任务，也没有重新读取本轮集群进度。

## 核心判断

保留 VGGT 作为主要生成表示是可以继续研究的；不能把当前 R7 失败解释成几何特征不可生成。但“VGGT 替换 VAE”已不足以作为贡献。需要说明这种表示支持了什么可验证的操作，以及这些操作为何使画质、空间一致性或利用新观测的能力更好。

建议的总问题是：**如何把几何重建模型的特征变成可以探索、补全和纠正的生成场景状态？**

推荐从“移动相机时可靠复用已知内容、生成新显露内容”开始验证画质，再研究“新观察纠正已有场景假设，同时保持不受影响的内容”。这两个阶段可以属于一个项目，但不能一开始同时加入长期动力学、多主体动作、任意交互和实时生成。

暂定叙事：**探索未知，保留已知，用新证据修正想象。** 一个研究题目可以是 *From Reconstruction to Revisable Imagination: Geometric Representations as Generative Scene States*。标题仅用于组织假设，没有对应已完成方法或结果。

本轮的 VGGT-as-RAE 定义：主要被扩散/生成的变量来自 VGGT 表示，最终 RGB 和几何由该表示解码。原生 VAE 视频生成器可以作为质量参照，但不能把其输出作为主生成结果，再以 VGGT 条件支路宣称完成了 VGGT RAE。允许重新设计压缩、场景适配、decoder 和训练目标；固定 VGGT 研究核心不等于永久冻结当前 C192 R7。

## MIRA 的故事为什么成立

[MIRA 论文](https://arxiv.org/abs/2607.05352)与[官方技术说明](https://mira-wm.com/blog-post/)使用四个同步玩家视角和对应动作，要求同一比赛中的事件在多个观察者那里保持一致。它可以测试动作影响、遮挡目标是否消失，以及增加视角是否帮助预测。

可借鉴的研究结构是“现有任务遗漏一种失败 → 新任务使失败可观察 → 方法利用新信息 → 有匹配对照”。不能从“底层用了 RAE”推出多人只是包装。SpatialVID 单路径视频没有四个同步行动主体；不能直接据此宣称多主体物理世界模拟。

## 一手文献查重：哪些叙事已经有人做

| 工作 | 已覆盖的核心内容 | 对我们的约束 |
|---|---|---|
| [GLD / Repurposing Geometric Foundation Models for Multi-view Diffusion](https://arxiv.org/html/2603.22275v1) | 直接扩散几何模型的多层特征；DA3 为主，附录验证 VGGT | 多视角 RGB/几何生成、替换成 VGGT，本身不是新贡献 |
| [Gen3R](https://arxiv.org/html/2601.04090v2) | appearance VAE 与 VGGT 几何适配 latent 联合扩散、分别解码 | 联合 RGB+几何已有；不要误写成其没有联合建模 |
| [OneWorld](https://arxiv.org/html/2603.16099v1) | 改造 π³ 得到统一几何/外观 RAE，跨视角对应监督，以及生成误差下的 decoder 适配 | 统一 3D RAE、几何一致损失、鲁棒 decoder 都不能单独作为新意 |
| [Any 3D Scene is Worth 1K Tokens](https://arxiv.org/html/2604.11331v1) | 将基础特征融合为固定数量的场景 token，生成后按相机查询视图 | “一个世界、多条轨迹、无需逐轨迹重新扩散”也已有直接工作 |
| [Latent Riemannian Flow Matching for Geometry-Grounded 3D Foundation Models](https://arxiv.org/abs/2607.19120) | 在 VGGT 的特定归一化特征接口中进行几何约束 flow | 直接 VGGT latent flow 已有；其球面约束不能直接套到当前压缩时序 R7 |
| [VGGT-World](https://arxiv.org/abs/2603.12655) | 在 VGGT 表示中预测未来几何 | 几何预测不等于完成清晰 RGB 视频生成 |
| [WorldWarp](https://arxiv.org/abs/2512.19678) | 几何传播，已覆盖区域与空洞采用不同扩散处理 | 已知区域复用、未知区域补全也不是空白 |
| [3D-Belief](https://arxiv.org/html/2605.11367v1) | 观测/想象的三维状态、多假设与新观测后的序贯更新 | 不能宣称首次区分证据与想象，或首次可修正世界 |

OneWorld 的论文 v1 实验写 Re10K+DL3DV；其[当前官方仓库](https://github.com/SensenGao/OneWorld)发布的 NVS-Refined 则包含 SpatialVid。数据 release 与原论文实验不能混写。

这里找到的是可研究的具体问题，不是一个已被证明无人涉足的领域。若贡献最终只有换 VGGT backbone 或把已有组件拼到一起，就应承认证据不足。

更宽的提法也需要收窄：[RecGen3D](https://arxiv.org/abs/2604.01479)已研究重建与生成的共同 canonical space；[WorldWeaver](https://arxiv.org/abs/2607.21594)已研究多主体共享状态；[Predicting 3D structure by latent posterior sampling](https://arxiv.org/abs/2605.10830)已研究由部分观测约束三维采样。因此“统一坐标”“共享状态”“用证据约束生成”也不是独立创新。

## 从当前实现得到的关键假设

现有 R7 对 geo/tex 特征做投影，再时序混合、压缩和 RGB 重建。它没有验证：压缩后几何仍可读、同一空间内容跨观察集合有稳定表示、特征可按相机运输、局部编辑只影响相应内容。分支名 `geo`/`tex` 也不证明解耦。legacy 整窗归一化不能直接充当前缀稳定的流式状态，但这不否定它作为固定窗 codec 的合法性。

因此值得研究的区别是：**能够重建的特征，与能够复用、查询和更新的生成状态，是不同要求。** 目前尚不能断言这种差别就是差画质的唯一根因。

GLD 有一处直接相关的实现：只用 source 视图编码条件，却联合生成 source+target 的目标特征，因为联合注意力会改变 source 部分。我们不能默认独立编码的首帧等于完整窗口编码后的首帧。该观察建议检查表示契约，不能仅靠看到这种差异就判定现有训练存在泄漏或错误。上下文增加后几何估计变好也会合法地改变特征，不应强迫所有层完全不变。[GLD §4.3](https://arxiv.org/html/2603.22275v1#S4.SS3)

## 候选一：能运输已知内容的几何 RAE

**中心问题：相机移动造成的画面变化，有多少可以由已知场景解释，有多少需要随机生成？能否在表示层使两者更容易分开？**

给定真实观察及目标相机，先将可信内容移动到目标视角，再生成缺失和修正量。可以用下式表达假设，而不是预设所有 VGGT feature 都能线性相加：

```text
observed RGB -> VGGT -> adapted scene features
                         |
                 geometry-aware transport/query
                         |
           generated novelty + appearance/geometry correction
                         |
                  RGB and geometry decoders
```

VGGT 的候选价值是提供跨视角对应、结构和遮挡信息，使表示里的内容可以复用。单纯知道深度不保证 learned latent 可运输；适配层需要为这个操作训练。反射、曝光、动态物体和错误深度需要软修正，不能把所有投影区域锁死。

**潜在贡献**：建立适合运输的 RAE，并用受控实验说明这种表示减少了生成器必须重新学习的视图变化，使相同预算下 RGB 更好。不能只报告残差范数更小；缩放可任意改变范数，误差小也未必视觉更好。

**先否证再扩大**：在少量真实多视角片段中，先只用真实源观察做运输；分别查看运输结果，以及用目标的真实缺失特征补齐后的诊断结果。后者是 oracle，只检查表示/decoder 的上限，不是生成成绩。若补齐后共同可见区域仍严重变形，当前 codec 不支持该操作，不能继续靠扩大 DiT 证明这个假设。learned adapter 可以修复，但必须在独立场景检验。

后续才比较完整 latent 生成与新增/修正量生成，匹配观察帧、相机、生成器容量和预算。报告共同可见与新显露区域的 RGB/LPIPS、几何、时间一致性、端到端耗时及实际算量。用 VGGT 与同容量 DINO/普通 depth+pose 的替代对照检查贡献是否确实来自该表示。WorldWarp、原生几何视频模型是外部质量参照；不能因任务设置不同而把其画质优势忽略。

一个更有辨别力的分析是将相机运动幅度和新增可见面积分开分组：在新增内容相近时，已知结构的大幅图像位移是否仍使质量明显恶化？目标是让生成负担更多随未知内容增长，而不是随整幅画面的位移增长。这是需要实测的趋势，不是复杂度定理。几何准确性尽量用独立重建/真值或干净合成数据评价；用 VGGT 自己的预测做标签只能检验信息保留，不能证明真实三维正确。

## 候选二：生成场景可以被新证据局部纠正

**中心问题：新真实观察推翻一个几何/外观假设时，怎样让所有相关视角得到一致修正，同时保留仍然成立的场景内容？**

演示可以非常具体：从街口看向遮挡建筑，模型补出一扇窗；新拍摄揭示那里其实是墙；更新后从其他视角看那扇窗也消失，但街道其他已确认外观不被重画。此处没有承诺模型会预知真实遮挡区域，只要求收到证据后正确利用它。

感知得到的特征和生成的假设进入同一 VGGT 派生场景表示。需要保存证据来源；自生成图像反复编码不增加独立真实证据。使用新的观测更新状态，再从该状态解码 RGB/几何。生成模式若没有新真实输入，只有想象分支延续，不能声称自动纠正到了真实世界。

3D-Belief 已经区分 observed 与 imagined Gaussians；其 §3.1 保留观测、以新想象替换旧想象。因此可能值得比较的更窄问题是：**基于新证据修正原有假设，是否比整体重新采样更能兼顾视觉稳定、证据符合和计算成本？** 这是待验证区别；可在同一方法内实现整体重采样对照，并与外部方法比较。不能仅因内部表示不同就认定有研究贡献。

“局部”是几何和证据关联意义上的局部；一个新的尺度或遮挡解释可能合理地影响大范围状态，不能硬性要求所有未直接观测像素不变。也不能把保持错误的旧样本当作成功。若需要评价跨更新稳定性，应明确耦合哪一个场景假设，而不只是沿用整数随机种子。

最小实验把帧拆为初始观察 O、新增证据 E、始终隐藏的评估视角 Q。所有推理条件仅含 O 或 O+E。比较更新前后 Q 的 RGB/几何改善，以及已有、与该更新无关的可验证区域是否受损；加入重复证据、错误场景证据、全部重编码/重采样、保存真实观测加简单 warp 等对照。重复证据不应被误算为新增独立支持；错误证据不必被强制融合。

帧互斥还不足以防止特征泄漏：O 阶段的特征、深度、归一化及运输置信度只能由 O 和训练集固定统计构造，不能先联合编码 O+E+Q 再切出 O。更新后允许 O+E，仍不能读取 Q。目标相机是允许的查询条件；Q 的 RGB、深度和联合编码特征只用于监督、评价或明确标记的 oracle，不进入推理条件。

需要严格区分“更多条件帧有帮助”与“更新机制有效”：O+E 从头运行是必要基线。关于顺序不变性，只能在同一静态场景、同一最终证据集合、相同预算下比较输出分布/指标；不能要求独立随机样本像素完全一致。

## 候选三：相机独立的动态世界

更远的故事是同一个动态事件可以被不同相机观察，镜头变化不改变事件本身。它比静态 NVS 更接近 MIRA 的交互世界模型，但要求同步多视角或可控模拟数据，才能验证同一物体的运动和不同动作的结果。

SpatialVID 单路径观察无法单独支撑这种反事实监督。把不同时刻当同步多视角、将倒放当真实回访，都会制造错误标签。不建议当前启动这条主线。WASD 也只是相机轨迹接口；没有物体交互数据时不能把导航称为已学会物理动力学。

## 数据与第一轮应当怎么限定

继续利用 HQ 可以支持前两条方向的初步研究，但组织单位应是具有可用几何和重叠的场景观察集合，而不只是类别名或所有固定 9 帧窗口。

- 先筛静态背景、足够视差、合理重叠、无切镜且位姿可信的片段。检查模糊、动态遮挡、轨迹尺度和稀疏相机标注对齐；不要只按街景/无人机二分。
- O/E/Q 必须互斥；跨 train/eval 尽量按来源视频及场景划分，不能相邻窗口穿越拆分。来源身份无法确定的场景应标记，而不声称无泄漏。
- 第一轮目标是受限短程场景探索的清晰 RGB。给定相机、增加允许的真实观察，是明确改变条件任务；不能与旧单首帧任意未来直接比较并归因为新表示的收益。
- SpatialVID 有真实连续观察，但并不保证回环、相反路径、独立多相机或动态反事实。需要这些实验时再增加带可靠真值的数据；未见轨迹演示不等于定量验证。
- 先用 16–32 个质量经过检查的场景做可视化筛查，并保留独立场景，不在这么小的样本上宣称 FID/FVD 显著结论。正式评估需要扩大的独立样本和预先固定的协议。

## 收敛为一个项目，而不是再开一串实验

推荐只设两个有先后关系的关口：

1. **表示与画质关口**：相同内容在不同上下文下的变化可解释；几何操作后的特征仍能解码；在多帧、小位移、短程任务上获得清楚且符合相机的真实生成结果。oracle 结果与生成结果分开。如果当前 R7 不适配，重做有操作目标的适配/decoder，而不是仅更改时序 norm 后沿用旧 checkpoint。
2. **科学贡献关口**：同等条件、预算下，运输/更新带来可重现的 RGB 质量与跨视角行为改善，并优于简单 depth warp、从头生成和已有场景生成方法。若换 DINO 或普通几何条件后一样好，就不能主张 VGGT 是关键；若只改善 latent MSE 或几何读出，不算达成用户的画质目标。

几何评估也应避免只由 VGGT 自己判定生成特征是否正确：结合数据相机、真实图像对应/重投影与可用真值，并区分真值和伪标签。只用同源任务头的改善最多证明表示自洽，不能替代 RGB 和真实结构证据。

候选一更接近解决当前画质问题；候选二提供更清晰的交互能力演示。若关口一未成立，不靠新名字推进“world model”。也不以单个最佳样例代替整个固定评估集。

现有 stage50 仍是一项已批准的相机条件对照，回答当前 R7 获得轨迹信息后的增益；它不验证本文场景状态、运输或证据更新假设。本文没有取消它或改变旧实验。任何后续实现继续沿用 OBS 双读双写、断点与中间结果、失败台账，以及字面格式 `DI_throughput: <value> tokens/s/npu`。

### 用户明确的近期目标：优于原生VACE的局部收益

用户随后明确：近期希望有可靠数值改善和可展示的优势case，不要求全面胜过基模。
应分别判断“完整方法对Native的收益”和“RAE对RGB控制的额外贡献”，不能用后者
尚弱否定前者的一切信号。当前Native指同source/anchor/mask/seed的原生参考条件
VACE，不是只有文本输入的另一种协议。

精确保存的JSON表明：24例learned的keep_change均比Native低，均值
.03224018 -> .03019709，下降6.337%。edit_region_change均值同时下降2.200%，

RGB的keep_change均值.03018289，仍比learned略低；该项收益主要来自共同传输/写回。

数值候选：三叶草keep偏离下降11.98%，edit区域变化增加3.07%；粉色水面分别

不自动扩大到任意拓扑改变、世界模型或要求所有编辑类型全面胜出。

- 木台`c8704e1e74aa41e5de913851`：参考木纹明显，成片主要剩橙色/棕色，

- 蓝笔`f9f9cea4e99d5433e5a9ea5c`：首帧已改错为蓝色纸张；三路延续错误，

## 方法上的限制与下一节点

1. **源光流可靠不等于编辑正确。** `models/edit_transport.py`中门控为
   `support * clamp(1-confidence/.95)`。confidence>=.95时完全不可修正。
   它保护了已知编辑，也会保护错误语义/错误纹理；可写区域的实测比例说明
   模块被限定为局部修补。未保存逐像素误差归因，不能断言这是唯一原因。
2. **训练目标停在中间参考。** 训练只优化中间RGB L1和latent正则，VACE在
   独立冻结阶段仅接受两次晚期写回。结冰/木纹说明可见参考没有可靠转为成片。
   这是本方法训练与接口设计的不足，不应归咎于数据不足或NPU没有生效。
3. **修正基底不完全匹配。** 训练在九时刻coarse-flow proposal上学习修正，
   预测却将其加到另算的17帧full-flow proposal上，只合并support。
   两套提议可能不一致；日志没有其差值，不能宣称已证实它造成损失。
4. **前端错误没有被解决。** 合法模型anchor不等于正确anchor；当前模块
   不读编辑指令，无法把改错的纸张重新定位为笔。

不建议继续扩大同一种小残差网络或仅延长训练。下一主要进度节点应是让
编辑状态成为生成器确实使用的条件：统一训练/推理的reference表示和对应基底，
训练参考条件注入与生成器的适配，并用最终编辑保持和未编辑区保持验证。
可解码RAE应在这个过程中提供可检验的编辑状态，而不是只交付一个更低L1的
中间图。保留Native＋参考和RGB条件两项强对照，未来还需匹配容量/训练量的
非RAE控制才能证明RAE独特贡献。此处是下一设计方向，尚未实现或启动。

## 数据、输入和指标先冻结

1. 先审计既有 128 reserved-test 的真实隔离情况。按原视频/场景组排除训练、
   monitor、已看过的 24 dev，以及锚帧前端训练的重叠；同源的不同指令不算独立源。
   元数据不足时增加视觉近重复检查，不能把文件哈希不同直接称作场景独立。
   若不够 128，从现有 pilot 其他源补足，不为数量勉强混入训练场景。
2. 主任务限于颜色、材质和局部外观，保持场景布局与原动作。按源输入预先标记
   静态、小运动、相机运动、物体运动、遮挡重现；报告实际各层数量，不按结果挑组。
   17 帧、8 FPS，沿用现有长宽比/面积上限/pad 与裁回逻辑。每个方法用相同真实时间点。
3. 保留两个输入协议：自动锚帧的文本端到端协议；文本 + 共享合法锚帧，必要时加
   源视频用户区域的传播协议。主验证先集中在后者以定位传输贡献，前者独立报告
   整条链路的失败。任何共同锚帧可来自固定前端或独立用户制作，不能取测试未来 GT。
   人工修正不能只给本方法。按预先制定的输入规则选例，不按哪个方法好看来选例。
   文本端到端协议先在主集预先固定的 32 例单独输出，所有自动锚帧失败均保留；
   用户区域协议另表，不把额外点击带来的提升称作文本理解提升。
4. 在同一协议中所有方法得到同一 source/prompt/anchor/region。Native+传播参考
   单独揭示额外预处理的作用；SFT 使用同一数据、LoRA 设置、采样和 checkpoint 选择
   规则，不能拿旧 48 例 SFT 对比新 1920 例 RAE 后归因于表示。
5. 主指标同时覆盖：指令/对象执行、编辑区外保持、源动作/布局、可见区域的效果
   一致性、自然度。CLIP 语义分数只作一轴；区域保持采用源视频人工核验的对象 mask
   或已有标注，独立于方法自己的 change-support。SAM2 可辅助源 mask，但必须核验。
   不以低帧差当作好运动，不以低背景误差当作完成编辑。
6. 时序评估尽可能采用与方法 DIS 不同的可用估计器或人工核验点轨迹。若独立权重
   未就绪，暂用人工核验与盲评，并披露 DIS 自评相关性；不把同一内部约束当独立证据。
   不用自身 VGGT 特征分数作为几何优越的唯一指标。
7. 按源视频聚合种子，再做配对置信区间；报告全体及预先定义的难例层。失败样本
   记录原因/覆盖率，不让某方法只在成功交集上获得更好均值。FVD 不作小样本主结论。

## 只安排一条效果改进主线

保留 Stage67 作为已验证回退版本。优先检验“校准后的参考同步进入原生 VACE
RGB 条件、state bridge 和 velocity”这一项；RGB 和 RAE 使用同样的更新机制。
当前原生 RGB 条件固定、另外两条路径变化是否限制收益仍是假设，不是已确诊根因。

先在旧 dev 上检查零编辑/no-op、状态影响、参考 prefix、坐标、采样器历史重置和
实际画面，再决定是否用此版本做匹配的 LoRA/bridge 适配。条件契约变更必须新
namespace，保留旧权重可复验；不能把旧 optimizer 当作新分布的无缝继续训练。
冻结 RAE/encoder/Wan 基础权重，不重新训练 AE 或更大 DiT。

训练首轮沿用审计过的 1920 对与 monitor；目标先补齐同条件 RGB/RAE/SFT，而非
同时扩数据和改模型。按开发集选 checkpoint；保存 1500/3000/6000 等预算节点。
6000 是排期上限，不是收敛声明；实际评估频率和早停保持可复验。若开发结果不支持
新条件版本，使用已验证版本完成主表，剩余任务继续，不无限追加架构试验。

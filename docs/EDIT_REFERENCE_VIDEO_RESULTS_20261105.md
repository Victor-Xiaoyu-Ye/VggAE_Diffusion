# Stage63 真实视频参考编辑结果审阅

日期：2026-11-05。本地结果：`D:/中转站/VGGAE/scale/edit_reference_video_v1`。

## 结论

三节点完整执行了真实视频参考、源光流传输、冻结 RAE 校准与原生 VACE
晚期写回。存在局部自然度改善，但没有建立可靠的编辑保持优势，更没有建立
RAE 独有的几何贡献。最明确的失败发生在写回前：RAE 校准本身就把部分目标编辑
拉回源视频，连无需跨帧对应的首帧也一样。不能把这种退回源图统称为结构保持收益。

这不是漏跑、没有加载适配器、回调未执行或本地媒体下载不全。下一步应修改
编辑参考保留与不确定区域修补的分工，而不是直接继续训练旧辅助 loss、扩大数据，
或只调大晚期写回力度。以下是结果审阅和后续建议；本次没有改动生产模型代码、
启动集群、上传 OBS 或把这些结果写成论文成功结论。

## 数字怎样读

原始 JSON 对照（24 视频等权平均，RGB 0–1）：

| 诊断 | Native+reference | RAE writeback | 解释 |
|---|---:|---:|---|
| 编辑区相对 source 的 L1 | 0.111998 | 0.092940 | 20/24 变小；可能减少错误，也可能撤回目标编辑 |
| mask 外相对 source 的 L1 | 0.035313 | 0.033949 | 22/24 变小，均值约减少 3.86%；不是编辑成功率 |

两路视频平均差异 L1=0.023976，证明方法改变了实际输出，不证明变化有益。
20 例使用自动参考差分支持，覆盖面积平均 74.09%，其中 9 例超过 80%、6 例超过
90%。另外 4 例是已有的人工源框。自动差分没有把“对象变化”与前端漂色、形变、
重建误差分开；局部编辑常常变成大面积重绘。

对本地 MP4 的补充计算去掉顶部 20 像素字幕，解码全部 17 帧。设 source 为 S、
RGB flow proposal 为 P、RAE reference 为 R，计算
`gain = <R-S, P-S> / ||P-S||²`。这只衡量沿原提议编辑方向的保留量，不是正确性。
H.264 和 uint8 误差仍存在；不能冒充原始 tensor 或正式 benchmark 指标。

- 全片 mean gain=0.56035；首帧 0.50913；第 8–16 帧 0.57885。
- 花圈/墓园 gain=0.2125，薄荷帐篷 0.3297，棕帐篷 0.5498，粉港湾 0.3235，彩蛋 0.2701。
- 最终 RAE 成片的编辑向量对 Native 成片的对应 gain 平均 0.81482。
- 同时存在非共线变化，不能说整套方法严格等价于一个 RGB 混合系数。

首帧已经显著衰减，排除了“全部由长程时序或未来帧光流造成”的解释。24 个求解
都在 sweep12 达到当前历史最低且仍下降；平均 objective 从 sweep1 的 1.11258
到 sweep8 的 0.70571，再到 sweep12 的 0.59828。最后一步还降低约 4.26%。
这是未证明收敛的证据；不意味着单纯加步数必然解决自然度或参考错误。

## 可定位的设计问题

1. **参考定位不可靠。** 共享参考由前端产生；蓝莓/笔等错误在这个阶段就存在。
   差分 mask 既不是语义 mask，也不能识别哪一处变化符合文本。错误参考经传输后
   不会自动变成正确指令。
2. **校准没有保住已知编辑。** `utils/editing_video_transport.py` 从零 delta 开始，
   每时刻 lr=0.02、12 次 Adam 更新；首帧仅使用 4 倍软拟合项，未锁定其可见效果。
   `edit_reference_video.py` 用 `solved_effect - coarse_effect` 修正 full proposal。
   首帧 full/coarse 相同且 confidence=1，所以首帧变成 `source+solved_effect`，
   原参考被尚未充分拟合的编辑替代。这是明确的实现/方法契约缺口，不是用户漏跑。
3. **RAE 分支内部引导可能冲突。** VACE 参考前缀仍是原 anchor，晚期写回却使用
   已经削弱编辑的 RAE reference。两路对照输入是匹配的，但 RAE 内部两种引导
   不再表达相同的编辑强度。采样后更像源图是这个设计可预期的结果之一。
4. **源光流适用范围有限。** 蝴蝶参考改变形状，源帧对应不能直接定义新翼形的
   跨帧关系；水面结冰改变了内容/几何，不能把它和保持形状的颜色传输等同。
   提高可见性置信度或延长求解无法独自解决这些问题。

未做因素隔离，因此不把全部损失归因于 12 次迭代、权重、AE 可达性或光流任何
单一因素；也不宣称这证明所有 RAE 编辑方法不可行。

## 下一个完整效果节点建议

保留同一个真实视频→编辑参考→完整原生渲染框架，直接修改主要瓶颈：

- 明确参考质量和对象支持。默认文本前端失败要计入端到端结果；另保留用户合法
  单帧参考+源点击/区域协议，不能拿数据集 target 充当参考或将额外控制算成更强文本理解。
- **首帧及高置信可见编辑作为要保留的观测。** 先可靠拟合参考，或保留观测中的
  像素残差；RAE 用来修复不确定对应、遮挡及不一致，不能无条件覆盖全部编辑。
  可解码性应该帮助判断哪些跨帧修正有效，而非只把结果投回未编辑的源附近。
- 求解采用实际收敛/拟合残差和合理最大预算；保存最优迭代，保留阶段视频。
  不以某个画质阈值中断整个任务，失败/不适用案例继续出独立结果。
- 一次完整出 Native、直接 RGB 传输写回、改后的 RAE 传输写回，条件与预算对齐。
  这三个完整视频是解释核心贡献所需的最少对照，不另起大批参数扫点。
  同时保留已成功的外观编辑和失败的形变案例，分别报告而不隐藏困难样本。

目标是 **在相当编辑强度下，减少闪烁、错位和背景污染，并保持预期外观**。
如果普通 RGB 传输或简单源混合就能同样做到，应接受该反证，不能把同样效果
包装为 VGGT 几何优势。当前尚不具备这一论文主结果。

# Scene RAE 三节点完整训练结果（2026-10-08）

## 2026-10-09 重要更正：低精度 EMA 使生成评估失真

重新审计发现**确定的数值实现错误**：本轮 `train_scene_pipeline.py` 将 EMA shadow 设为 BF16，`utils/training.py` 在 shadow 精度内分别执行 `mul_(decay).add_(value, alpha=1-decay)`，decay 为 0.9995。旧 `train_r7_window_diffusion.py` 使用 FP32 EMA。本轮所有 image/video 预览都先 `ema.copy_to(model)`，没有原始 online 权重的生成对照。

小更新会被 BF16 舍入吞掉，也可能出现不同参数不一致的偏移。用实际 PyTorch 2.7.1+CPU 和原仓库 EMA 类复现：成熟 EMA 初始为 1、online 固定改成 1.5，更新 10,000 次后，BF16 仍为 **1.0**，FP32 为 **1.49646**（理论 1.49664）。启用 warmup、online 在 20,000 步中从 1 平滑升至 1.5，BF16 最终仍为 1，FP32 为 1.45181。这个问题不是普通推理 BF16 autocast；它发生在长期累积的 EMA 参数状态中。

还从 OBS 的 6 个真实 checkpoint 读取 ZIP 元数据和 10 个指定参数张量片段，共 **5,533,942 bytes**，未下载 GB 级 checkpoint。model 存储是 FP32，EMA 是 BF16；最终 metadata 的 num_updates 等于真实训练步数。每个大张量取前 8,192 个存储元素，小张量取全量，**不是对全模型冻结比例的估计**：

| 阶段及区间 | 张量 | 抽查 EMA 元素完全不变比例 | 同位置 online 变化 |
|---|---|---:|---|
| image 10,490→16,394 | input.weight | 100% | 全部变化 |
| image 10,490→16,394 | widen.weight | 100% | 全部变化 |
| image 10,490→16,394 | output.1.weight | 99.939% | 全部变化 |
| video 9,185→137,104 | output.0.weight（1,536 个） | 100% | 全部变化 |
| video 9,185→137,104 | output.1.weight | 94.348% | 全部变化，相对 L2 变化 57.37% |

单图相邻评估每例 RAW L1 改变量的中位数从 2,042→4,145 的 0.01516 降至 14,706→16,394 的 0.0000535，与实际权重停滞相互印证。不能把这解释成 online DiT 在同一时期也停止学习。

**撤回此前从 EMA 坏画面直接推导“单图 DiT 没有学会、整轮训练不能生成”的判断。** 已证实的是 EMA 数值更新有误、已展示的 EMA 样例失败。online 网络是否达到可用质量还没有经过对应的自由采样。image→video 初始化和断点恢复都读取 `model`，没有拿损坏的 EMA 初始化视频网络；原始训练权重仍有评估价值。转换旧 EMA 到 FP32只会停止继续丢精度，不能补回丢掉的历史，也不能称为恢复了正确 EMA。

修复范围：后续 Scene trainer 使用 FP32 EMA；EMA 恢复尊重目标 dtype 并记录低精度历史，保留原状态、不静默重置。只需额外约 1.55 GiB/卡的常驻 EMA 存储，仍需实测实际恢复峰值。原始产物保持不变；优先重采样已有 online image 终点、video 中期/终点，使用相同样例/seed/32 步与旧 EMA 配对，再加64步。不要根据损坏 EMA 的 9,185 步最小 L1 选择“最佳 online checkpoint”。

## 2026-10-09 同时存在的设计变化与证据边界

这些变化已由代码/manifest 确认，可能增加生成难度，但目前没有隔离其各自的画质影响：

| 维度 | 旧 stage49 Full-HQ | 新 stage51 Scene |
|---|---|---|
| DiT 参数量 | 1.653B，1536×24 | 0.831B，768×24 主干 + 1536×6 头 |
| future latent | 4×18×18×192 | 8×18×18×256，标量目标 2.667 倍 |
| 固定训练窗口 | 1,440,144 | 69,800，少 20.63 倍 |
| 数据 | SpatialVID Full-HQ | 7 来源；SpatialVID 仅 8192 街景+256 replay |
| 图像共训 | 无独立图像阶段 | 24h 图像阶段 + 视频每4次更新一次图像 |
| 参考首帧 | 视频训练始终提供 | 视频任务20% reference dropout |
| 推理 | 64步 Euler，文本 CFG3 | 32步 Euler，CFG1，且仅评低精度 EMA |
| 评估集 | 32个街景、2 seeds | 27个跨域样本、1 seed，与旧32例ID无交集 |

1. **数据跨度增加不等于样本更多。** 17,450 个来源各固定4窗口，缓存完成数量正好匹配，并无大规模数据丢失。单图训练只拿每窗口独立 anchor，最多69,800个固定图；不会轮换另外8帧。image阶段约1259万次图像抽样，视频阶段又约2632万次图像抽样。video-only约987万窗口抽样，平均141次/window；此前519是视频阶段 image+video 混合抽取的平均，不能称作519次完整视频训练。Spring仅136窗口，按rank0外推video目标平均复用约1836次；这表明多样性有限，尚不足以证明过拟合。
2. **多视图帧和有时间基准的视频被送入同一 future 任务。** DL3DV/ScanNet/MVS占57.5%抽样权重，loader标记 `temporal_valid=False`，但cache未存这个标记，flow未来8槽一视同仁。DL3DV本身来自视频，不能称无序照片；本loader却没有原始fps/间距核验。WAI静态来源按过滤坏帧后的列表取stride1/2，可跨编号间断；ScanNet样例实际有DSC00963→DSC00972。只有Point/Spring明确拆相机、数值排序并取连续段；SpatialVID/Omni约1秒。模型无时间间隔/任务类型条件。这些数据可以支持多视图生成，但不能假设天然构成同一时间语义的视频任务。
3. **图像预训练大多没有文字，相机控制也并非大面积提供。** 仅SpatialVID取caption，按源权重67.5%抽样无caption，text-drop后约70.75%。按确定无相机的6118/7716旧DL3DV路径、全部SpatialVID及Omni路径计算，无相机抽样期望至少66.7%，再加camera-drop20%后至少约73.4%。这是代码与源权重推导的下限，不是逐cache实测。不能把这轮称作充分的图文预训练和相机条件生成。
4. **更好的重建不保证更易扩散。** 增加通道、去掉时域压缩会保留更多信息，也让生成器承担更多变量。AE PSNR提高是正结果，尚未衡量生成误差下的decoder鲁棒性。独立anchor/joint-future的差异旧版也有，未发现本轮新增的首帧编码契约错配。
5. **online训练末段确有异常，不能全归咎于EMA。** stage=video的13,710条记录全部task=video：日志每10步在step自增后触发，而image任务按自增前step%4==0，导致共训image loss完全漏记。video loss中位110–120k为0.14381，125–130k为0.24095，135k后0.39902；这是真实online视频训练损失上升，并非混合任务统计造成。权重片段确认online为FP32，不能把它无证据归为BF16参数训练。先评估终点及120k之前的raw模型，再决定是否存在可见退化。

这次最先应处理的是**确定的 EMA/评估问题**，其次才是上述任务与架构变化；不能用“VGGT不适合生成”概括当前证据。诊断小文件和只读range工具在 `D:/workspace/VggAE_DataAudit/scene_regression_20261009/`。

代码修复通过29项CPU测试（5 EMA、12 Scene、12旧Window）、Python编译及diff检查。集成测试覆盖FP32恢复、原始snapshot不被修改、online/EMA分别输出以及两类任务日志。真实910B重新推理、原始权重画质及新增EMA内存峰值尚未验证。

## 重建已改善，生成仍不合格

固定验证 AE 的平均域 PSNR 从 19.379 升至 **25.872 dB**。终点同案例样本均值为 25.810 dB，旧 R7 为 24.380 dB，配对平均 **+1.429 dB**。`ae/complete.json` 选择同为 9,126 步的 `best_joint.pt`。多数 RAW/AE 画面对照显示场景内容保持清晰。OmniWorld 比旧 R7 低 0.450 dB；SpatialVID 仅高 0.330 dB。各域新/旧均值如下。

| 来源 | 新 AE PSNR | 旧 R7 PSNR | 配对变化 |
|---|---:|---:|---:|
| DL3DV | 29.223 | 27.469 | +1.754 |
| MVS-Synth | 24.555 | 22.648 | +1.907 |
| OmniWorld | 24.448 | 24.898 | −0.450 |
| PointOdyssey | 23.299 | 21.331 | +1.968 |
| ScanNet++ | 28.935 | 27.003 | +1.932 |
| SpatialVID | 23.090 | 22.759 | +0.330 |
| Spring | 27.552 | 24.609 | +2.943 |

单图训练 loss 中位数约 0.448→0.327，最终固定样例 AE 重建 L1 为 0.0367；末期 16,394 步的 27 例 EMA 自由生成均出现重影、拼贴及局部纹理破碎，早期 2,042 步抽查的 4 例也有类似问题。固定样例 `raw_l1` 0.2637→0.2640；**无条件自由生成与一张指定真实图像的像素距离本身不是可信质量指标**。画面检查证明这些 EMA 样例不合格；依上方10月9日修正，不把它外推为online网络也失败。

视频固定 27 例的未来帧 L1 最低是 **9,185 步 0.1637**，末期升至 **0.1732**；复制首帧基线为 **0.1347**，终点仅 3/27 例更低。固定样例 AE L1 为 0.0392。训练 loss 在 110–120k 步中位约 0.144，125–130k 为 0.241，135k 后为 0.399，末端还有尖峰；说明后段存在明显退化风险。9,185 步的 `weights_step0009185.pt` 仍在 OBS，但在四例同案例的三时点视觉对照中，较早权重也未出现可靠的结构稳定性，不能因为它的像素 L1 最小就称作最佳视频。`video/complete.json` 当前选择最终 checkpoint，未按视觉质量择优。

视频样例三栏依次是 RAW、AE、GENERATED；**GENERATED 的第 0 帧是直接拼入的真实参考 latent**。只看第 1–8 帧才是在评估扩散器。最终 27 例中可见部分街道/建筑大致轮廓，但室内、合成场景和游戏对象常在前几帧变成纹理拼贴，出现物体消失、重复立面和时域结构漂移。不能把第 0 帧的清晰度或 AE 重建质量记作生成质量。这个观察覆盖本次固定 27 例与所述三时点，不代表所有训练分布。

最终 27 例中仅 **4 例有 caption，16 例有相机条件**；SpatialVID 4 例均无相机，DL3DV 4 例仅 1 例有相机。现有样例无法支持“已经验证 geometry-aware 生成”的结论，也没有相机控制的对照实验。缓存 69,800 个窗口；按 rank0 外推24 rank，视频阶段约987万次视频抽样及2632万次图像抽样。此前合计约每窗口519次，实际video-only平均约141次。这是**训练抽样次数**，不是独立视频数量。当前证据不足以把后段 loss 升高归因于某一个坏来源。

## 对项目的判断与下一步

本轮有AE能够重建及cache完整的证据。10月9日确定EMA更新精度有误，**必须先比较保存的online原始权重与旧EMA**；此前单图/视频坏样例不能排除评估权重失真。任务混合、表示扩散难度、采样器和decoder敏感性仍是次级待测解释。

下一步先用现有冻结 AE、图像终点和视频 9,185/终点权重做一轮**推理与统计诊断**，不用启动新的 15 天训练：

1. 在相同固定验证 latent 上，按多个噪声 `u` 比较真实加噪后的单步 `x0` 误差、其 RGB 解码及各通道/空间频率误差，分离训练目标拟合与自由 rollout 失败。
2. 比较 32 步 Euler、更多步数/Heun、EMA 与原始权重，以及视频早期/终点同种子的 latent 范围和解码画面，排除采样器/EMA 与权重选择问题。
3. 对训练与生成 latent 做均值、方差、频谱、跨通道相关性和 decoder 扰动敏感度对照，验证“好重建但生成 latent 难扩散”的具体环节。
4. 先取得可辨认且稳定的单图自由生成，再扩展视频与几何控制；之后专门保留有相机条件的验证子集，加入有/无相机、真实/扰动轨迹对照。单次固定种子的像素 L1 只作辅助，质量决定还要看多种子视觉与结构指标。

## 2. 最有判别力的实验：分别替换生成结果的两半 latent

当前表示是 `[z_geo(128), z_texture(128)]`。以下仅修改生成结束后的解码输入：

- GT geo：`D(z_geo_GT, z_texture_generated)`。
- GT texture：`D(z_geo_generated, z_texture_GT)`。
- AE：`D(z_geo_GT, z_texture_GT)`。

指标为原始浮点 RGB 上未来五帧的平均 L1，越低越好。没有使用有损预览计算本表。

| 案例 | AE | 生成 | 换 GT geo | 换 GT texture |
|---|---:|---:|---:|---:|
| 000 | 0.040040 | 0.060078 | 0.060205 | 0.039848 |
| 004 | 0.041233 | 0.100233 | 0.099974 | 0.041553 |
| 007 | 0.036854 | 0.109516 | 0.109806 | 0.036198 |
| 011 | 0.039852 | 0.084348 | 0.084097 | 0.040081 |
| 024 | 0.030791 | 0.077069 | 0.077099 | 0.030150 |
| 036 | 0.024675 | 0.057808 | 0.057688 | 0.024806 |
| 041，AE 异常单列 | 0.298213 | 0.342885 | 0.341274 | 0.297890 |
| 048 | 0.033917 | 0.086726 | 0.086566 | 0.034111 |
| 全部 8 例 | **0.068197** | **0.114833** | **0.114589** | **0.068080** |
| 其余 7 例，041 保留在上表 | **0.035337** | **0.082254** | **0.082205** | **0.035250** |

七例中 GT geo 仅恢复生成到 AE 的 L1 差距的 **0.10%**；GT texture 基本恢复到
AE 水平。后者略低于 AE 不代表超过理论重建上限，只是这个解码器的混合输入结果。
七例平均逐例 PSNR 为 AE 24.81 dB、生成 17.35 dB；全部八例为 22.94/16.25 dB。

实际查看全部八个六列联系图。004/011/024/048 的行人重影、腿部透明和轮廓错误，
在 GT geo 图中仍明显，在 GT texture 图中大幅恢复；007 的近景人物也有同样趋势。
000/036 的背景漂移并非完全由动态物体引起。

结论是**这批生成到重建的差距主要来自 texture 分支预测**，不是已经证明
“几何毫无用处”或“只差一个更好的 decoder”。生成误差、表示可建模性与解码敏感性
仍有耦合；八个定向选择案例、单 seed101 也不是总体无偏评测。

特别注意：后处理替换 GT geo 没收益，不能推导出**在去噪过程中以几何指导纹理**
没有收益。这是不同的干预，Stage57 没训练或测试后者。

## 3. 当前表示不是严格分离的几何与外观

`models/scene_rae.py` 的 geo 来自冻结 StreamVGGT 特征的可学习压缩；texture
来自直接读取 RGB 的可学习 encoder。两半一起构成生成目标，并非推理时偷读未来
RGB，也不是 RGB decoder skip。但它也不是“只对纯 VGGT 特征做扩散”。

`restore_features` 读取全部 C256，relation loss 也约束整个表示，不能保证几何
信息只存在 geo 半边，或 texture 半边只存细节颜色。texture 可以同时承载轮廓、
位置和外观。因此 GT texture 消除人物重影，并不证明人物位置只由纹理定义。

八例干预进一步说明这一点：

| 干预，clean AE 输入 | 相对原 AE 的 RGB L1 变化均值 |
|---|---:|
| geo 原始数值置零 | 0.108878 |
| geo 替换成训练均值 | 0.014625 |
| geo 替换成其他案例的对应分支 | 0.016540 |
| texture 替换成训练均值 | 0.291888 |
| texture 替换成其他案例的对应分支 | 0.259107 |

geo 置零有明显影响，不能称它完全断开；原始零值可能是分布外输入，也不能用这一项
证明强几何依赖。均值/跨案例替换相较 texture 的影响小很多。发表所需的几何贡献，
还需要独立几何读出、同等参数的非几何对照及真正的条件干预证据。

## 4. 不是简单的 latent RMS 太大

将每例实际生成误差和独立 Gaussian 噪声匹配到同一分支的相同 normalized MSE，
再比较解码结果相对 clean AE 的误差：

- texture 的实际误差导致 RGB L1 是等 MSE 随机误差的 **1.36–2.06 倍**，RGB MSE
  是 **2.47–4.41 倍**，八例一致。
- geo 的对应 L1 比例为 **0.87–1.26 倍**，没有同等级的稳定放大。
- 匹配是整段分支全局 MSE，未逐通道/逐频率/逐帧匹配，且每例仅一个随机方向。

这说明实际 texture 误差的结构更伤画面。它不定位唯一原因，也不证明随机噪声增强
完全无效，但不足以支持继续仅调整全局 jitter 或仅用 latent loss 选择最佳模型。
八例平均生成相对 AE 的 RGB L1 从第一未来帧 0.04440 增至第五未来帧 0.10387。
这是同一次固定窗口预测的帧间差异，不应误称为自回归长视频误差累积。

## 5. StreamVGGT tracker：FP32 没修好，坐标本身也有问题

8 组 BF16/FP32 × real/repeated-first × case000/004，分别运行 full9/prefix4。
16 个实际 teacher/LK `.pt` 均可读，72 个 teacher 封存成员完整。

- 59,904 个神经 point-frame 观测无一合格；confidence 为 `6.61e-11–1.63e-9`。
- 所有输出有限，frame0 坐标与 query 完全一致，16 次层级 instrumentation 完整。
- confidence logits 为 -23.44 至 -20.24，而 head bias 仅 -0.0402。
- 相同首帧重复九次时，后八帧 neural tracks 仍平均漂移 **22.63/14.67 px**，
  最大 **125.95/62.85 px**；FP32 几乎相同。独立 LK 的合格点位移严格为零。

因此不能通过降低分数阈值、将置信度置 1、或切换 FP32 宣布修复。有限输出与
参数成功加载不等于有效 tracking。当前证据尚不能唯一归因于 checkpoint、实现
语义或共同运行时；未做新后端/官方环境的严格同输入复现。

## 6. LK 恢复了对应，但未证明动态 mask 或 reference 质量收益

| 真实案例 | full LK 合格观测 | v2 future 运输支持 | 运输 texture L1 | copy-last texture L1 |
|---|---:|---:|---:|---:|
| 000 | 2978/5184 | 1344/1620 token | 0.45550 | 0.38741 |
| 004 | 2394/5184 | 1283/1620 token | 0.58709 | 0.58559 |

这是相同支持区域上的 normalized texture 指标，不能与前面的 RGB L1 混用。
运输相对 copy 的 L1 分别差 17.57%/0.26%，还没有稳定优于简单复制。
正确对应相对打乱 destination 的共同支持区域 L1 好 20.45%/12.58%，故对应确有
信息；004 全支持区域 MSE 改善约 4.16%，共同支持区域 L1 改善约 1.06%。
不能概括为 LK 完全没用，也不能由此声称人物画质已改善。

旧版几何一致性分类中，两例均没有 dynamic tracks；004 的 576 个点全部 unknown，
因为窗口 frame_index=2..8 的几何一致性检查不可靠。未知不能当静止，重复图无误报
不能证明动态召回。v2 输入按设计移除了未来 depth 派生类别，所以也不能把 v2 的
零 dynamic 通道误当检测结果。此轮没有可用于评价动态区域收益的有效动态标签。

LK 运输检查使用从完整真实视频提取的未来 tracks，是条件可用时的效用诊断；它
没有从观察前缀预测未来运动。密集几何图、语义 mask 和用户 WASD 也不能直接互换。

## 7. case041 必须单独修查，不能归咎于扩散或回放

暗色街廊案例在观察帧的 AE 重建里就已明显整体提亮；未来 GT texture 替换后仍亮。
AE RGB L1 达 0.298213，其他七例为 0.024675–0.041233。这是 AE 重建链路异常，
未证明是某个模型参数、缓存编码、预处理或数值精度的具体 bug。

回放有差异的案例是 007/024/041/048。041 最大 uint8 通道差 193、差异通道
0.7242%，并非全是 ±1 舍入；但平均差只有 0.216153/255 = **0.000848**。
由三角不等式，更换这两份 raw 对 AE L1 的影响最多约 0.000848，解释不了 0.2982。
没有保存差异空间图，不能凭均值猜测水印/边框。

后续应在相同权重下重编码 cached raw 与 replay raw，对照 saved latent、新 latent、
编码/解码精度及单帧/窗口输入，定位哪一步提亮。先保存中间张量，避免再次只留预览。
本地尚无完整 AE/源缓存 payload，不能声称此项已修复。

## 8. 下一步取舍

本轮只记录结果，未新增训练、修改阈值或替换 teacher。建议更新实验顺序：

1. **停止扩大当前失效的 tracking/reference 方案。** 神经 tracks 不可用，LK 运输
   也未达到稳定降低纹理预测难度的证据。不得把旧 B/C 再跑长一些当作充分修复。
2. **下一个小训练优先回答“几何能否指导 texture 去噪”。** 保留 AE/统计量/源 DiT，
   在固定运动子集上对照同构的 prefix-only 与未来 GT geo 条件下的 texture 预测；
   相同数据、预算和噪声，训练后检查正确/打乱/置空几何。GT geo 支路必须标为 oracle
   上界，不能当可部署生成；下一阶段才用预测或用户条件可获得的几何替换它。
   这项与本轮解码后替换不同，能判断几何在去噪中是否有可用价值。若仅 oracle 有效，
   问题还包括实际几何条件的获取，而不是已经完成方法。
3. **独立做有边界的 decoder 对照，而非盲目重训整个 AE。** 使用训练集对应的实际
   去噪误差测试短程修正，保留 clean 重建锚点和冻结 encoder；不得拿八个 eval 样本
   拟合。区分受控/近 GT 的去噪误差与无条件多解未来，避免强迫任意有效未来匹配
   唯一 GT 而进一步平均化。必须同时观察 clean AE、动态轮廓、静态细节是否退化。
4. **case041 重编码定位与上述实验并行**，异常记录不被平均值隐藏，也不因一个样本
   阻止无关实验。结果始终同时报全体和预声明的异常分层。

这些是建议的下一轮实验，不是已经实现的新方法或启动脚本。不能从本轮保证训练
质量，也不能说增加数据/模型容量永远无用；只能说已有更具体的失败点应优先检验。

论文主张仍需要“几何确实减少外观生成困难”的对照证据。当前结果反而说明双分支
命名不等于有效分工。若几何条件的 oracle 都不能改善 held-out texture 生成，就应
重新设计表示/解码组织，而不是继续围绕 track mask 包装叙事。

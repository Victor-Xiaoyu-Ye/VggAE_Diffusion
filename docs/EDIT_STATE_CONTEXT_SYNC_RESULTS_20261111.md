# Stage68 实际结果：条件同步生效，新增画质收益未建立

审阅日期：2026-11-11。
结果目录：`D:/中转站/VGGAE/scale/edit_state_context_sync_v1`。
审计与逐帧对照：`D:/workspace/VggAE_DataAudit/stage68_review/`。

## 核心结论

本轮完整结束。RAE/RGB 的新状态不仅写入 bridge 和去噪修正，也成功刷新了
VACE 的 reactive video context，并在后续去噪步使用。最终无损输出确实变化，
不能再把本轮结果解释为“条件根本没有接进去”。

但是，同步前后的实际画面没有出现稳定、明确的新改善。RAE sync 的
keep_change 比 RAE joint 高 0.705%，只有 8/24 例下降；RGB sync 相对 RGB
joint 高 0.040%，基本持平。匹配同步协议后，RAE 的 keep_change 比 RGB
高 3.467%，18/24 例更高。此指标不是完整画质，逐帧审阅也未建立 RAE 的
整体优势。蝴蝶尾段躯干/翼的局部优势可以保留，但在同步前就存在。

对 Native 的蓝蝴蝶持续编辑、木吧台纹理、彩蛋旁手部保持等收益仍然存在，
但 RGB 也有，且不是本轮新增收益。错误编辑对象、抹除源结构、幻觉参考
没有通过同步得到纠正。因此，本轮不支持“旧 context 冲突是主要瓶颈，
同步后即可明显改善画面”的预期；只否定当前时间点/强度下的这一充分性
假设，不能推广成所有条件同步方法都无效。

## 本轮究竟比较了什么

- 七臂，各 24 个 development cases，17 帧、8fps、30 步、seed42。
- 使用 Stage65 已选定的 RGB/RAE 权重；本轮没有重新训练 AE、VACE 或 adapter。
- `native`：本项目原生 VACE 对照。
- `rgb_base` / `rae_base`：已有状态分支，无在线反馈。
- `rgb_joint` / `rae_joint`：回溯求解，更新编辑状态、bridge 和速度，保留旧
  native RGB context。
- `rgb_sync` / `rae_sync`：同一配置，额外同步 native reactive video context。
- 同步在 sampling index 20/25/28 发生，各例三次。只刷新相应 reactive
  video channels，日志记录 prefix、inactive source 和 mask channels 保持。
- 这些是旧 24 例开发集，不是独立主实验测试集，不具备新的 SOTA/泛化证据。
  Native 与状态分支的整体差异也不能全部归因于 RAE 表示。

## 完整性、运行和证据边界

- 三节点及全部协调阶段退出 0。最终 summary child 原始返回码 0、signal=null；
  上轮 smoke 的汇总退出异常没有在本轮重现。日志明确启用了 CPU-only summary。
- 七臂 168 份最终 MP4、168 份无损 NPZ 齐全，四个反馈臂的 288 份中间视频齐全。
- 共检查 888 个本地声明实体文件，大小/SHA 无错误；552 个 MP4 全量解码，
  均为 17 帧/8fps；168 个最终 NPZ 的形状、uint8 像素及 fps 检查通过。
- 相同案例的 input identity/seed、同族 checkpoint/generation 配置及比较顺序
  已配对检查。三基线标记为 reused；四个反馈臂重新生成。
- media_sync 记录 checked=480、failed=[]。这是下载结果和运行记录的审阅，
  没有重新访问 OBS 验证当前两端对象。
- 本地 480 个 `.pt` 只有 receipt，没有张量实体。因此没有独立重载中间
  latent/context 张量；同步的数值证据来自逐事件记录，最终影响来自无损像素。
- 三节点日志各有一次主 AE 路径 FileNotFoundError，随后 OBS fallback 成功，
  对应阶段退出 0。没有把这条已恢复的探测误报为整轮失败。
- 从首个协调阶段开始至 node0 退出约 94 分 40 秒，排除 bootstrap/smoke。
  本地有 DI_throughput 记录；包含 IO/reuse，不能作为纯模型推理速度比较。
- RAE 峰值 allocated 40.009 GiB；RGB 37.026 GiB。两组运行墙钟并非干净的
  性能实验，不以本轮 RAE sync 较快的墙钟宣称加速。

## 最终输出指标

`keep_change` 是传播支持区外相对源画面的像素变化；支持区不是语义真值
mask。`edit_region_change` 只是支持区内变化幅度，不能越大就算指令执行
更好。`output_frame_delta` 不能区分平滑运动、冻结与纹理丢失，不作为质量排名。

| 版本 | keep_change | edit_region_change | output_frame_delta |
|---|---:|---:|---:|
| Native | 0.03248491 | 0.09942934 | 0.01835755 |
| RGB base | 0.02411247 | 0.11490237 | 0.01385951 |
| RAE base | 0.02473683 | 0.11568093 | 0.01370803 |
| RGB joint，固定 context | 0.02332335 | 0.11407669 | 0.01385516 |
| RGB sync，同步 context | 0.02333272 | 0.11463152 | 0.01384585 |
| RAE joint，固定 context | 0.02397255 | 0.11421191 | 0.01390462 |
| RAE sync，同步 context | 0.02414157 | 0.11426928 | 0.01392573 |

- RGB 同步：keep 增加 0.040%，10/24 例下降；编辑幅度增加 0.486%。
- RAE 同步：keep 增加 0.705%，8/24 例下降；编辑幅度增加 0.050%。
- RAE sync vs RGB sync：keep 高 3.467%，18/24 例更高；编辑幅度低 0.316%。
- 对 Native：RGB sync 的 keep 低 28.173%，RAE sync 低 25.684%。这些整体
  改善在固定 context 分支已存在，不能作为同步或 RAE 独有的收益。

按案例配对 bootstrap（10,000 次、seed42）的描述性 95% 区间：
RGB sync−joint 的 keep 差为 0.00000937，区间 [-0.00014067, 0.00012989]；
RAE sync−joint 为 0.00016902，区间 [-0.00000392, 0.00038046]。
不能称为显著退化，也没有改善证据。RAE sync−RGB sync 的 keep 差为
0.00080885，区间 [0.00008225, 0.00156788]。这些区间只描述当前反复使用
的开发集，不是新独立样本的确认性统计结论。

## 对后续工作的约束

1. 保留 RAE 编辑状态＋VACE＋对应/几何约束方向。同步可保留为实现选项，
   暂不以它为主性能贡献，也不据本轮默认替换固定 context 的最佳结果。
2. 本轮是一个有意义的负结果：数值优化、状态写回、条件刷新均发生，
   但拟合目标和最终编辑正确性仍然脱节。单纯加求解步数或继续以“没接通”
   解释结果，没有当前证据支持。
3. 参考意图/对象定位与源结构保护优先。当前操作没有可靠信号告诉模型
   “改笔而非图纸”“水可改色但浮桥必须保留”“床不应新增花束”。同步
   一个有误的参考，并不会自动得到这些约束。这是机制解释，不是已经
   证明的唯一根因；具体新的可靠性/结构方案仍需验证。
4. 如果后续仍用 RGB 光流对应，应准确称为源图像对应，不能把内部对应
   loss 的下降写成最终视频三维几何一致性的提升。
5. 后续保持相同前端/参考/条件/预算的 RGB 对照。所有 Native 优势和精选
   RAE 局部优势要分别列出，不能把系统整体收益写成 RAE 的独有收益。
6. 本次只审阅产物、制作实际像素对照并更新文档；没有改训练/采样代码，
   没有重训、提交集群任务或把本轮开发集结果升级为论文主实验。

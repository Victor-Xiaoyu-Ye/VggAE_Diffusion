## 最关键的工作

**建立“正确编辑参考 → 自然视频中的同一对象 → 实际 native 输出”的链路。**
当前最大的可执行缺口是没有把明确的编辑样板、合法对象支持、跨帧对应和
RAE 编辑状态接到同一次真实视频生成中。更多数据或辅助 loss 不能替代这条链路。
这不是已证明的全部失败原因；是依据现有结果/代码选出的最高优先级工程方向。

已具备：真实17帧源缓存、生产RAE、原生VACE14B/NPU采样、LoRA、双读双写。
Stage62 已证明 decoder 可用于校准直接 token 传输；尚不能假定它能从稀疏
色块自行补出正确外观。下一版让 RAE 校准已经合理的编辑提议，不再从零猜编辑。

## 首个成片节点的定义

给定真实源视频、一张编辑过的参考帧和可选源对象区域，输出完整17帧编辑视频：
编辑对象持续呈现目标外观，背景不被大片污染，人体/物体按源运动变化，边界和
遮挡处不明显拖影或破碎。先做保持形状的外观/纹理编辑；暂不混入物体新增、
几何变形、重光照和相机重定向。颜色案例保证调试直观，但最终展示不能只有色偏。

这一步给出实际成片，不以校准PNG、辅助loss或重复首帧作为交付结果。
17帧用于复用现有缓存和资源估算；固定窗口时长后续按真实数据与效果扩展，
不引入自回归长视频前置依赖。

## 主路径与实现顺序

1. **明确改成什么：共享编辑参考。** 保留两种输入协议：文本由固定前端生成
   reference；或用户提供编辑参考/源区域的交互方式。已有SFT/regionSFT输出的
   固定首帧可复用为model-anchor，但其失败必须保留并归为前端失败。不能把
   Señorita edited target 偷作实际推理参考，也不能从target挑最好的模型帧。
   如现有模型参考明显不足，升级独立单帧编辑前端；不再长训RAE去纠正错参考。
2. **接入官方原生参考条件。** VACE已支持reference、源视频、mask组合。
   自定义runtime此前只接视频和mask，benchmark也过滤了reference cases。
   现已新增 `pack_context(..., reference_images=...)` 和 `decode_native`：
   参考分别做image-mode编码，置于latent前缀；reactive/reference mask用零；
   采样保留这些前缀参与attention，VAE解码前移除。不是把RGB参考拼成第18帧。
   **接口接入不等于完整成片流程已经实现或效果已验。**
3. **确定在哪个对象上持续修改。** 首批复用现有source-only开发框；接入已有
   SAM2权重用于源对象mask传播。SAM2接口/910B尚未验证，不把checkpoint存在
   当作已可用。mask解决区域，像素对应仍需要source flow/feature匹配及双向
   一致性/遮挡权重。旧Stream track重复帧漂移不可作为默认可靠主依赖。
   不允许把线性插值框称作物体跟踪，或把相机移动当作动态物体。
4. **维护共同编辑，再交给生成器渲染。** 对应传输得到合理RGB提议，原生
   reference VACE补充难区提议；RAE从提议初始化，在多个源状态中联合维护
   同一个编辑效果，用 `D(z+delta)-D(z)` 保留源细节并校准可见变化。未知/
   新显露区域保留生成器提议，不硬拷贝上帧、不将其强制判静态。
5. **作用到最终视频。** 先将完整编辑参考作为native条件，再接晚期clean
   estimate/velocity写回。写回使用编码差值抵消VAE往返偏置，遵循设计文档的
   sigma约定；必须看到实际主输出改变，不能只增加旁路readout。保存写回前后
   视频和实际增量，便于在同一作业内定位问题。

参考、对应/RAE预处理、14B生成按阶段串行加载并缓存，避免把多套大模型同时
常驻。保持原始比例/FPS/有效区域；17个native视频帧与9个RAE观察时刻分别记录，
reference latent prefix不属于源时间轴。所有阶段继续双读双写、逐case恢复、
阶段保存、明确DI单位及现有idle guard。数据坏例跳过并汇总，质量差不阻止其他case。

## 一次作业的交付与效果判断

首轮只保留两条完整视频输出：同参考/同源区域/同seed的原生reference VACE，
以及加入RAE传输与实际写回的完整版本。其余RGB/VAE/DINO、无校准/无对应等
通过模块开关预留，效果建立后再批量剥离；当前不宣称独有性已经被验证。

每个case一起保存源视频、参考图、源区域、传输提议、native基线、完整方法视频，
统一帧索引、FPS和有效画面。主评价分别看编辑执行、对象细节/形状、运动与背景保持，
不把接近source或不编辑当成功。代表案例必须包含自然运动、相机运动、复杂纹理；
展示可以选择说明性案例，但完整开发集合的失败也记录。

工程检查只关注会使结果失效的错误：参考前缀/时间裁剪、实际条件接入、归一化和
坐标、无target泄漏、写回恒等性及保存恢复。它们不扩张成下一轮研究探针矩阵。
没有给效果设自动门槛来中止后续case，也不因反例启动更多辅助loss长训练。
